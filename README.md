# DocSeek

DocSeek 是一个面向 Windows 办公环境的本地全文检索工具。目标不是做一个“能搜正文的 Demo”，而是把 **Everything 的即时、简洁、低资源体验** 与 **Recoll/DocFetcher 一类全文检索工具的内容索引、相关性排序和预览能力**结合起来，并针对中文 Office 文档和内网办公本进行优化。

## 核心原则

- **完全本地**：不上传文件内容，不依赖云服务。
- **搜索与解析解耦**：文件内容提前建立索引，搜索时不遍历磁盘。
- **增量更新**：未修改文件不重复解析，降低 CPU、内存与磁盘压力。
- **界面始终可响应**：耗时索引在后台线程执行，可主动停止。
- **普通用户优先**：默认直接输入关键词即可，不要求学习复杂检索语法。
- **可解释结果**：显示文件名、路径、修改时间、命中上下文，并按相关性排序。

## 架构

```text
指定工作目录
    ↓
DirectoryIndexer
    ├─ 文件扫描
    ├─ mtime + size 增量判断
    ├─ 大文件保护
    └─ 删除检测
    ↓
Extractors
    ├─ 文本
    ├─ Word
    ├─ Excel（read_only 流式读取）
    └─ PDF（逐页提取）
    ↓
SQLite
    ├─ files：文件元数据
    ├─ settings：索引配置
    └─ FTS5：正文倒排索引
    ↓
BM25 Search
    ↓
结果列表 + 命中预览 + Windows 文件操作
```

## 性能策略

DocSeek 不会在用户输入关键词后逐个打开文件。文件读取发生在索引阶段，查询只访问 FTS5 倒排索引。

为了适合普通办公本，目前采用：

- SQLite WAL，允许索引写入和搜索读取更平滑地并存；
- 文件 `modified_time + size` 判断是否发生变化；
- Excel 使用 `read_only=True`，避免整本工作簿加载到内存；
- PDF 逐页提取正文；
- 单文件默认 200 MB 保护阈值；
- 搜索输入 220ms 防抖；
- 单次最多渲染 150 条结果，避免结果列表一次塞入数万项。

### P2：中文检索专项优化

SQLite FTS5 默认分词对中文不是最佳方案，因此不会把当前实现当作最终中文检索方案。计划评估：

1. FTS5 trigram / n-gram；
2. 本地中文分词后写入索引；
3. 精确短语、前缀和模糊匹配的组合；
4. 中文查询纠错与搜索建议。

所有方案都以 **离线、低资源、可打包部署** 为约束进行基准测试后选择，而不是为了“先进”盲目增加依赖。

### P3：可选智能检索

后续可加入本地 Hybrid Search：

```text
FTS5 / BM25 关键词召回
          +
本地 Embedding 语义召回
          ↓
       重排序
```

语义检索只作为可选增强，传统全文检索始终保留，以保证内网环境中的速度、稳定性和可解释性。

## 开发运行

建议 Python 3.11 或 3.12：

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -e .
docseek
```

索引数据库默认存放在：

```text
%USERPROFILE%\.docseek\docseek.db
```

## 项目定位

DocSeek 现阶段优先解决：

> 文件很多、文件名记不住，但记得正文中的关键词，希望像 Everything 一样快速找到 Word、Excel、PDF 等办公资料。

在这个目标稳定实现之后，再逐步增加更高级的检索能力。
