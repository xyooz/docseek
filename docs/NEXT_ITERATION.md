# DocSeek 下一迭代：First Successful Search

## 当前目标

DocSeek 已经具备完整技术链路：

```text
选择目录 → 解析 → 建立索引 → 搜索 → 预览 → 打开文件 → 自动更新
```

下一阶段不以增加功能数量为目标，而以普通 Windows 办公用户能否稳定完成一次真实搜索为验收标准：

> 用户安装或解压 DocSeek，选择资料目录，已完成的内容可以搜索，找到目标文件并打开；后续文件变化自动收敛，用户不需要理解索引、FTS、WAL、Chunk 或 Schema。

## 执行追踪

本文负责说明阶段目标和决策原则；每日实施状态、P0 完成度、真实 Beta 证据、性能前后数据和被否决实验统一记录在：

- [`FIRST_SUCCESSFUL_SEARCH_TRACKER.md`](FIRST_SUCCESSFUL_SEARCH_TRACKER.md)

后续只有“代码完成 + CI 通过 + 对应真实 Beta 场景通过”的产品项，才视为真正完成。

## 功能冻结

在第一轮真实 Beta 证据形成前，暂缓以下扩展：

- OCR；
- 语义/向量检索；
- USN/MFT 增量扫描；
- 新的复杂资源调度系统；
- 更多高级查询语法；
- 因没有实测瓶颈而替换 SQLite FTS5。

只有真实 Beta 结果证明这些能力是主要阻塞点时，才重新进入对应研发。

## P0：可重复通过的核心链路

### 1. 启动后自动校准

已配置目录在每次启动后自动进行一次后台 reconciliation，补齐 DocSeek 关闭期间发生的新建、修改、重命名和删除。已完成索引内容在校准期间仍可搜索。

### 2. 目录配置先于首次扫描持久化

用户确认资料目录后，先保存索引范围并立即启动 watcher，再启动首次扫描。扫描取消、异常退出或断电不会使 DocSeek 忘记用户已经选择的目录；下次启动通过自动校准自然继续。

### 3. 索引数据位置可配置

控制文件仍保存在用户配置目录；真正占空间且包含提取正文的 `docseek.db / -wal / -shm` 支持迁移到本机其他磁盘。

迁移原则：

```text
用户选择新位置
→ 当前运行只记录待迁移请求
→ 正常关闭
→ 下次启动、SQLite 尚未打开
→ SQLite backup 到目标临时库
→ quick_check / Schema 校验
→ 原子切换目标库
→ 更新位置配置
→ 再启动 GUI
```

任何校验或配置切换失败都继续保留旧库为权威数据，不在运行中直接复制 WAL/SHM。

### 4. 首次使用路径

无索引目录时，界面只需要让用户理解三件事：

1. 选择资料目录；
2. DocSeek 在本机建立索引，不上传文档；
3. 已完成索引的内容即可搜索。

历史、收藏、排序、复杂筛选等能力保留，但不应成为第一次使用的认知负担。

### 5. 可理解的索引状态

目标状态表达：

```text
正在发现可搜索文件…

已发现 3,200 个文件
已完成 860 个 · 更新 426 个
已完成的内容现在可以搜索
```

完成后：

```text
索引已更新 · 3,200 个文件
```

有问题时：

```text
索引基本完成 · 3 个文件未能处理
```

不向普通用户暴露 WAL、reconciliation、extractor revision、chunk 等内部术语。

## 第一轮 Beta 验收

先验证小而真实的场景，不直接追求 50,000 文件：

- 3～5 台普通 Win10/Win11 办公电脑；
- 每台 500～2,000 份真实、已获准测试的办公文档；
- 每台至少 20 条已知目标查询；
- 记录 Top1 / Top5 / Top10、是否需要改写查询；
- 双击目标文件可以正常打开；
- 新建、修改、重命名、删除能够自动收敛；
- 应用关闭期间的变化在下一次启动后自动收敛；
- 首次扫描中断后能够自然恢复；
- 问题文件不会阻塞整体索引；
- 可把索引数据放到非系统盘；
- 连续运行一天，无明显 CPU、内存、数据库/WAL 异常增长；
- Setup 与 Portable 均以普通用户权限工作，不依赖 Python。

## 决策规则

真实 Beta 结果决定下一步技术投入：

```text
搜不到原词/表达差异多 → 领域词、同义词或语义检索
扫描 PDF 图片件很多    → OCR
后台明显影响办公        → 资源调度
大目录 metadata 扫描慢  → 先优化普通枚举路径；仍不足再评估 USN/MFT
FTS5 经测成为瓶颈       → 评估其他检索引擎
```

在这些证据出现之前，优先修复安装、恢复、更新一致性、索引生命周期、搜索可用性和真实用户体验问题。

## 当前 Beta 证据

- Windows CI、检索质量、目录扫描和自动化回归持续作为防回归保护，但不替代真实办公机验证。
- 真实 Portable 测试曾暴露 `database is locked`。已定位并修复多层目录惰性发现与 SQLite 批量 writer 自锁问题，并新增针对性回归测试；后续真实测试暂未再次出现该错误，当前状态记为“继续观察”，不宣称彻底消失。
- 真实办公目录测试新增性能证据：添加一个稍大的目录后，“准备建立索引”阶段等待偏长，首次索引开始后的整体吞吐也偏慢。当前先优化普通文件系统发现路径，已将 discovery 阶段逐目录的 SQLite 问题状态写入收敛为批量事务，并跳过无排除配置时不必要的路径解析；保持“完整发现结束后再进入内容 writer”的锁安全边界。具体性能实验和当前数字以执行追踪文档为准。
- 下一步以实际 Setup/Portable 包继续跑完整用户路径，并把发现的问题作为优先级最高的迭代输入。
