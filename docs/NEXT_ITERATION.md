# DocSeek 结构定位与搜索自救迭代

## 定位

面向 Windows 内网办公终端的轻量级本地全文检索工具。保留 Python / PySide6 / SQLite FTS5，以及扫描、watcher、周期校准的基础路径。

## 本轮实现

- DOCX 保留段落与表格顺序，标题边界分块；提取版本递增，触发选择性重建。
- 文本编码检测只读取前 64 KiB。
- PDF 页和 XLSX 行范围按需预览，独立子进程、15 秒超时、关闭终止、输出大小限制。
- XLSX 显示真实行号和列字母；首行参考不等于已识别表头；长区域与内容有显示上限。
- 预览前后检查文件元数据，发现源文件变化则提示重新检索。
- 零结果显示运行中索引、问题文件、暂停目录的相关信息。这些是范围级诊断，不断言某个问题文件就是目标文件。
- 一次点击移除元数据筛选，保留关键词、引号短语与结构提示；设置入口用于检查范围、暂停和问题文件。

## 验证方式

运行完整 unittest，包含真实 PDF/XLSX 预览、窗口进程管道、UI 操作、DOCX 结构回归；运行仓库常规 CI 的编译、检索质量、1k 搜索、持久会话和扫描基准。

Windows 安装包生命周期、目标 Win10 环境和真实办公机长时间运行仍需部署环境验证。源代码测试不替代最终 frozen 交付物测试。

## 后续阶段

1. Word 标题层级与结构排序逐步使用独立字段；真实查询基线。
2. 在现有任务恢复之上增强版本保护和资源调度；真实繁忙办公机验证。
3. 经用户语料验证后，引入可选领域词扩展、OCR、完全相同副本聚合。
4. 只有测量发现瓶颈后，评估 MFT/USN 或替换搜索引擎。

本轮没有实现完整文档树、OCR、语义检索、USN 或新的调度系统。

## 第二轮已实现

- Schema v11 新增结构附加表；新写入保存独立位置字段，删除 chunk 同步清理附加表。旧库升级不重写正文，通过旧标签兼容读取。
- 搜索结果携带结构位置；PDF/XLSX 预览优先使用独立字段。
- 文档内匹配块按文档顺序分页浏览，后台读取、取消、SQL 超时、索引变化提示。
- watcher 增量更新复用 ChunkBatchWriter，正文和提取成功状态一并提交。
- 提交前源文件身份/元数据与取消检查；变化标记 PENDING，删除移除索引，失败回滚保留旧内容。

当前生产排序公式仍保持原有规则，结构标签兼容路径保留。结构表随文件自然重建逐步填充；没有一次性全库回填。文件系统与数据库之间仍存在最终检查到提交的窗口，后续事件和校准负责修复。
